# housing-calendar: LH 공고가 사라지고 무순위가 안 보이던 문제를 고친 기록

## 문제: "LH가 안 나온다"는 애매한 제보

housing-calendar를 쓰던 중 "LH 데이터가 안 나오고 청약홈 무순위가 비어 보인다"는 증상을 발견했다. API 키도 정상, 요청도 정상 응답을 받고 있었다. 결국 문제는 응답을 읽는 쪽에 있었다.

## 원인 추적: 필드명부터 하나씩 실측

LH 응답을 뜯어보니 공고게시일 필드가 코드가 기대하던 `PAN_NT_DT`가 아니었다. 코드는 이 필드를 먼저 보고 없으면 `PAN_DT`로 폴백했는데, 실측 617건 중 221건(36%)이 이 필드에서 빈 문자열이었다. `startDate`가 `''`가 되면 `index.ts`의 `startDate >= '2026-01-01'` 비교에서 조용히 false가 되어 삭제되는 구조였다. 지역 필드도 마찬가지였다. 코드가 참조하던 `CNP_NM`은 존재하지 않는 필드였고, 실제 필드는 `CNP_CD_NM`이었다. 이 탓에 LH 전건의 region이 '전국'으로 떨어져 서울/경기/인천 지역 필터를 누르면 LH 공고가 한 건도 남지 않았다. 이게 사용자가 체감한 "LH가 안 나온다"의 직접 원인이었다. 여기에 페이지네이션이 아예 없어서 `ALL_CNT=617` 중 page=1의 100건만 받고 517건을 통째로 버리고 있었다는 것도 확인했다.

청약홈 쪽은 데이터 자체는 285건이 정상 수집되고 있었다. 문제는 구분이었다. 배포 데이터 609건이 전부 `type='APT'`였고, 운영 페이지 HTML을 확인해보니 '무순위'라는 문자열이 0회 등장했다. 상세 화면에서 공급 일정 블록이 무순위 건에서만 항상 사라지는 것도 확인했는데, `specialSupply`/`generalSupply` 관련 네 필드를 아예 채우지 않고 있었기 때문이다.

텔레그램 알림 스크립트도 원인이 따로 있었다. `scripts/telegram-notifier.mjs`가 앱의 수집기를 재사용하지 않고 사본을 따로 두고 있었는데, 그 사본의 LH 호출부가 폐기된 엔드포인트를 부르고 있었다. 청약홈 쪽도 일반 APT 1페이지만 보고 무순위 엔드포인트는 호출조차 하지 않고 있었다.

## 해결: 필드명 교정, 페이지네이션, 사본 제거

LH 쪽은 `PAN_NT_ST_DT`로 필드명을 바꿔 빈 건을 0/617로 만들고, 마지막 페이지까지 전진 수집하도록 페이지네이션을 추가했다. 지역 필드는 `CNP_CD_NM`으로 교체했다. 토지·상가 공급공고(617건 중 261건, 42%)는 자동차정류장용지·제조시설용지 같은 비주택 공고여서 주택 일정을 덮고 있었기에 제외했다. 다만 목록에 없는 새 유형은 남기기로 했는데, 조용히 사라지는 쪽이 더 나쁜 실패이기 때문이다.

청약홈은 무순위를 `type=REMNDR`로 분리하고 제목에 표기를 붙였다. 값이 있는 32/285건에 대해서는 특별공급/일반공급 필드도 채웠다. 참고로 페이지 부족이나 dedup은 원인이 아니었다는 점도 전체 대조로 확인했다.

텔레그램 알림은 사본을 없애고 `generate-ics.mjs`가 이미 쓰던 `getAllSubscriptions()`를 그대로 쓰도록 바꿨다. `.ts`를 동적 import하므로 tsx 실행이 필요해서 `scripts/notify-run.mjs`를 새 엔트리로 추가했다. 죽어 있던 안내 링크도 실제 배포처로 고쳤다.

## 남은 것: 조용한 삭제를 드러내는 로그

이번 원인이 정확히 "startDate 빈 값이 연도 필터에서 조용히 삭제되는" 경로였는데, 증상은 그냥 "데이터가 안 나온다"로만 보여서 추적이 오래 걸렸다. 그래서 `index.ts`에 소스별 필터 제외 건수를 로그로 남기도록 했다. 함께 타입에 `REMNDR`을 추가하고 `SUBSCRIPTION_TYPE_LABELS`를 Record로 강제해 라벨 누락 시 내부 코드값이 그대로 노출되는 것도 막았다. lint, tsc, next build 모두 통과했고 최종 894건(청약홈 538 + LH 356)으로 정적 페이지 894개가 생성되는 것을 확인했다.
