## unslop은 어떤 문제를 해결하는 스킬인가

unslop은 Claude Code와 Codex에서 쓰는 스킬로, AI가 바이브코딩으로 만들어낸 뻔한 UI를 디자인된 인터페이스로 바꿔줍니다. 프로젝트 README에 따르면 보라색 그라데이션, 글로우 효과, 이모지 라벨, 과장된 카피, 들쭉날쭉한 간격 같은 '슬롭(slop)' 징후를 먼저 찾아내고, 제품 특성에서 방향성을 잡은 뒤 디자이너가 레드라인 리뷰를 하듯 단계별로 화면을 고칩니다(https://github.com/heydamir/unslop/blob/a6f121eee5f29c2f74976b75456feae8b66afb3a/README.md).

Next.js, React, Vue, Svelte, Tailwind, 순수 HTML/CSS까지 스택을 가리지 않고 동작한다고 밝히고 있고, 대시보드나 앱뿐 아니라 링크만 있는 라이브 사이트에도 적용할 수 있다고 README는 설명합니다. GitHub 저장소 정보 기준으로 2026-10-29에 공개됐고 star 9461개, fork 488개를 기록하고 있어 짧은 기간에 관심이 집중된 것을 확인할 수 있습니다.

## 설치하고 실행하면 실제로 뭘 하는가

README에 적힌 설치 방법은 명확합니다.

- Claude Code: 저장소를 클론한 뒤 `skills/unslop` 폴더를 `~/.claude/skills/`(또는 프로젝트 내 `.claude/skills/`)에 복사합니다.
- Codex: 스킬 설치 명령으로 저장소에서 바로 설치하거나, `~/.agents/skills/`에 수동으로 복사합니다.
- 라이브 사이트 스냅샷이나 스토리 영상을 만들려면 Playwright와 Chromium을 추가로 설치해야 하고, 스토리 영상은 ffmpeg까지 PATH에 있어야 합니다.

실행은 Claude Code에서 `/unslop`, Codex에서 `$unslop`을 입력하는 방식이고, 화면을 감사(audit)한 뒤 방향을 제안하고 나서야 수정에 들어갑니다. README는 작업 순서를 감사-방향-패스(간격, 색상, 아이콘, 카피, 타입, 레이아웃, 디테일, 비주얼, 모션 순)로 설명하고, 히어로 이미지가 필요하면 fal, Replicate, OpenAI, Higgsfield 같은 이미지 생성 서비스를 연결해 쓸 수 있되 유료 생성 전에는 매번 확인을 받는다고 명시합니다(https://github.com/heydamir/unslop/blob/a6f121eee5f29c2f74976b75456feae8b66afb3a/README.md).

## 내 프로젝트에 붙인다면 뭘 확인해야 하는가

실무에 넣기 전에 점검할 지점이 몇 가지 있습니다.

- 라이선스가 CC-BY-4.0이라 상업적 이용은 되지만 출처 표기(크레딧, 저장소 링크)가 필수라는 점을 README가 강조하고 있어, 사내 배포 전에 라이선스 고지 방식을 정해둬야 합니다.
- 스킬이 코드를 직접 수정하는 구조라서, 적용 전후 diff를 git으로 관리하지 않으면 의도치 않은 레이아웃 변경이 묻힐 수 있습니다.
- 이미지 생성 연동은 외부 유료 API에 의존하는데, README는 생성 전 프롬프트를 보여주고 승인받는다고만 설명할 뿐 과금 상한이나 실패 시 처리 방식은 적혀 있지 않아 여기까지는 확인되지 않습니다.
- 스토리 영상 기능은 Playwright와 ffmpeg라는 별도 의존성을 요구하므로, CI 환경이나 경량 컨테이너에서 쓰려면 이 부분이 걸림돌이 될 수 있습니다.

다음으로 확인할 것은 examples 디렉터리의 두 예시 화면을 직접 돌려보고, 실제 팀 코드베이스의 컴포넌트 구조에서 패스별 수정이 얼마나 안전하게 적용되는지 diff로 검증하는 작업입니다.
