## Mika는 정확히 뭘 하는 앱인가

Mika는 안드로이드 기기에서 동작하는 온디바이스 AI 에이전트입니다. 프로젝트 README(https://github.com/wangzan101/Mika/blob/0091d2d67b541a417df913a23fefbb8e3a04e4a7/README.md)에 따르면 핵심 동작 방식은 화면 하나를 백그라운드로 띄워서 그 위에서 앱을 터치하고 타이핑하고 스크롤하는 것입니다. 사용자는 메인 화면을 그대로 쓰면서, 원할 때만 작은 라이브 뷰를 눌러 진행 상황을 볼 수 있다고 설명합니다.

API 연동이 아니라 화면을 보고 버튼을 찾는 방식이라는 점이 특이합니다. README는 이를 "사람이 하듯" 화면을 읽어서 앱별 통합 없이 어떤 앱에도 적용된다고 설명합니다. 실무 관점에서 보면 이 방식은 앱 업데이트로 UI가 바뀌면 바로 영향을 받을 수 있다는 뜻이기도 합니다. README에 안정성에 대한 구체적 수치는 없어서, 이 부분은 여기까지는 확인되지 않는다고 봐야 합니다.

## 모델 연동과 프라이버시 구조는 어떻게 되어 있나

README에 따르면 Mika 자체 서버는 없고, 사용자가 직접 모델 API 키를 넣거나 ChatGPT, xAI, OpenRouter 계정으로 로그인하는 구조입니다. API 키와 메모리는 기기에 암호화되어 저장되고, 대화와 실행 기록도 기기에만 남는다고 합니다. 업데이트 확인만 GitHub과 통신한다고 명시되어 있습니다.

지원 모델 프로바이더는 다음과 같이 폭넓게 열려 있습니다.

- DeepSeek, 통의천문, Kimi, 지푸, 실리콘플로우, 화산방주, MiniMax 등 중국계 프로바이더 프리셋
- Anthropic, Gemini, OpenAI, xAI, Mistral, Groq, Ollama, LM Studio 등 해외 프로바이더 프리셋
- 위 목록에 없는 프로바이더는 Custom으로 OpenAI 호환, Anthropic, Gemini, OpenAI Responses 엔드포인트 지정 가능

내 프로젝트에 붙인다면 가장 먼저 확인할 부분은 이 프로바이더 선택과 키 관리 흐름입니다. 서버가 없다는 건 개인정보 측면에서 장점이지만, 반대로 말하면 멀티 디바이스 동기화나 중앙 로그 수집 같은 기능은 구조적으로 없다는 뜻입니다.

## 실제로 돌리려면 어떤 조건이 필요한가

README는 기기 요구사항을 기능별로 나눠서 제시합니다.

- 채팅, 웹, 파일 기능만 쓰려면 Android 11 이상
- 폰 앱 조작 기능은 Android 12 이상, Android 14 이상을 권장(백그라운드 화면이 별도 포커스를 가져서 메인 화면 타이핑을 방해하지 않는다고 설명)
- 리눅스 샌드박스(Python, Node, 셸 실행)는 arm64 기기에서만 동작

설치는 Settings › Recovery & repair의 호환성 자가진단 기능으로 12가지 항목을 1분 내 확인할 수 있다고 합니다. 기본 동작 모드는 Ask 모드로, 결제처럼 돈이 드는 작업 전에만 확인을 받고 나머지는 자동으로 처리하며, Autonomous 모드로 전환도 가능하다고 README는 설명합니다. 라이선스는 Apache-2.0이고 코드가 전부 공개되어 있다는 점도 명시되어 있습니다.

실제로 써보려면 Releases 페이지에서 APK를 받아 설치한 뒤, Settings의 "Set up phone control" 마법사로 무선 디버깅을 한 번 페어링하는 과정이 필요합니다. 다음 확인할 것은 본인이 쓰는 앱이 README의 "built-in usage knowledge" 목록에 있는지, 없다면 실제로 화면 인식만으로 얼마나 안정적으로 동작하는지 직접 테스트해보는 일입니다.
