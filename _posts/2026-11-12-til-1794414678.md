## GestaltX는 무엇을 건드리는 도구인가

GestaltX는 iOS와 iPadOS용 MobileGestalt 에디터입니다. 프로젝트 README에 따르면 디스플레이, 디바이스, iPad 전용 설정, 인텔리전스 관련 플래그, 그리고 애플 내부용 기능 플래그까지 건드릴 수 있습니다(https://github.com/huamidev/GestaltX/blob/144c0c44a762db616089faddfbc0581929ae1a0a/README.md).

MobileGestalt는 iOS 내부에서 기기 모델, 지원 기능 여부를 판단하는 캐시 레이어입니다. 이 캐시 값을 직접 편집한다는 것 자체가 공식 API 바깥의 작업이라는 점을 먼저 짚어야 합니다. GitHub 저장소 정보 기준으로 이 프로젝트는 2026-11-09에 공개됐고, 작성 시점 기준 star 6044, fork 2366을 기록하고 있습니다.

## 실무자가 먼저 확인할 조건은 무엇인가

README에 적힌 설치·서명 조건을 보면 일반적인 사이드로딩 앱과는 결이 다릅니다. 다음 조건을 먼저 확인해야 합니다.

- 지원 범위는 iOS/iPadOS 27.x뿐이고 26.x에서는 온디바이스 MobileGestalt 접근이 안 됩니다(README).
- 서명 시 최소 하나의 공통 App Group을 포함한 인증서와 프로비저닝 프로파일이 필요하고, 임베디드 공유 익스텐션도 함께 서명해야 합니다(README).
- 배포되는 IPA는 개발자 인증서가 아니라 ad-hoc 서명이며 SideStore, AltStore 재서명을 전제로 만들어졌습니다(README).
- forcequitOS의 worse_query 프로젝트를 기반으로 SystemGroup 접근을 구현했다고 README에 명시돼 있습니다.

이 조건들만 봐도 일반 앱스토어 배포 경로와 무관한, 탈옥 생태계에 가까운 설치 흐름입니다. 사내 기기에 테스트로 올리려 한다면 서명 인프라(App Group 포함 프로비저닝)를 먼저 준비해야 합니다.

## 내 프로젝트에 넣는다면 무엇이 걸리는가

이 도구는 라이브러리나 SDK가 아니라 독립 실행 앱이라서 기존 프로젝트에 '통합'하는 개념은 아닙니다. 대신 iOS 플랫폼을 다루는 개발자 입장에서 참고할 지점은 MobileGestalt 필드 구조와 백업/복원 로직입니다.

README는 CacheExtra 필드의 읽기·검색·추가·편집·삭제, plist 임포트·익스포트, 쓰기 전후 자동 백업과 검증된 쓰기를 지원한다고 설명합니다. 변경 전 원본 값을 기록해두고 되돌리는 구조라서, 설정값을 직접 조작하는 디버깅 도구를 만들 때 백업-복원 설계를 참고할 만합니다.

다만 README는 "Presets modify capability flags; actual effects depend on the device and OS"라고 선을 긋고 있습니다. 즉 같은 플래그를 켜도 기기 모델과 OS 버전에 따라 동작이 다를 수 있다는 뜻이라, 실제 효과를 기기별로 재현 가능한지는 README만으로는 확인되지 않습니다. 라이선스는 GPL-3.0이라 코드를 참고해 파생 작업을 할 때 공개 의무가 따른다는 점도 함께 체크해야 합니다.

다음으로 확인할 것은 Releases 페이지의 실제 IPA 서명 상태와, worse_query 저장소가 어떤 방식으로 SystemGroup 접근을 구현했는지입니다.
