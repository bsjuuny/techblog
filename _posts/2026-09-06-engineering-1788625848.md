# ipo-master /admin 페이지, 통째로 지운 이유

## 문제 발견: 토큰이 브라우저에 그대로 노출됨

ipo-master에는 `/admin` 페이지가 있었다. 로그인 게이트를 통과하면 GitHub Contents API를 호출해서 `competition_override.json`을 직접 읽고 쓰는 구조였다.

문제는 이 기능을 구현하면서 GitHub Personal Access Token, ADMIN_KEY, TOTP_SECRET을 전부 `NEXT_PUBLIC_*` 환경변수로 넣었다는 점이다. Next.js에서 `NEXT_PUBLIC_` 접두사가 붙은 값은 빌드 시 클라이언트 JS 번들에 그대로 박힌다. 즉 배포된 사이트에 접속한 사람이면 누구나 devtools로 번들을 열어 토큰을 뽑아낼 수 있는 상태였다. 이 토큰은 별도로 revoke 대상으로 플래그된 그 유출 토큰이다.

## 원인 파악: 애초에 이 경로가 필요했나?

먼저 든 생각은 "그럼 토큰만 서버사이드로 옮기면 되지 않나"였다. 하지만 배포 파이프라인을 다시 보니 `deploy-override.yml`이 이미 `competition_override.json` 파일 변경을 감지해서 git push 기반으로 도는 구조였다.

다시 말해 브라우저에서 GitHub API로 파일을 쓰는 건, 이미 존재하는 git push 기반 배포 흐름과 똑같은 결과를 만들기 위해 굳이 보안 위험을 감수하며 우회로를 하나 더 만든 셈이었다. 서버사이드로 토큰을 옮기는 정도로는 해결이 아니라 미봉책이었고, 이 기능 자체가 애초에 불필요한 중복 경로라는 게 원인 파악의 결론이었다.

## 해결: 브라우저 write 경로를 삭제하고 로컬 CLI로 대체

`src/app/admin/page.tsx`를 통째로 삭제했다. 로그인 게이트, GitHub API 읽기/쓰기 로직까지 558줄이 한 번에 사라졌다. 대신 `scripts/edit-override.mjs`라는 로컬 전용 인터랙티브 CLI를 추가해서, 디스크 위에서 `competition_override.json`을 직접 편집하고 원하면 git add/commit/push까지 하도록 만들었다.

두 워크플로 파일(`deploy-override.yml`, `deploy.yml`)에서도 `NEXT_PUBLIC_ADMIN_KEY`, `NEXT_PUBLIC_GITHUB_TOKEN`, `NEXT_PUBLIC_TOTP_SECRET`을 전부 제거했다. admin 페이지가 없으니 빌드 타임에 이 값들이 필요 없어졌기 때문이다. 더불어 admin 페이지에서만 쓰던 `otplib` 의존성도 정리해서 package-lock.json 92줄이 줄었다.

## 겸사겸사: eslint 설정 구멍도 메움

이번 변경을 다시 lint 검증하다가 `eslint.config.mjs`에 Next 기본 ignore 설정이 빠져 있는 걸 발견했다. FlatCompat 마이그레이션 과정에서 `.next`, `out`, `node_modules`를 무시하는 기본 설정이 누락된 상태였다.

이 커밋의 본질과는 무관한 기존 문제였지만, 재검증하는 김에 한 줄 추가해서 같이 고쳤다. 결과적으로 이번 커밋은 보안 구멍 하나를 막으면서 배포 흐름을 원래 있던 git push 기반 경로 하나로 단순화한 작업이었다.
