## DigUp은 정확히 뭘 하는 도구인가

DigUp은 컴퓨터 안의 파일을 내용 기반으로 검색하는 도구입니다. 저장소 설명에 따르면 사진, PDF, 문서, 녹음 파일, 영상, 코드까지 다 대상으로 삼습니다.

파일명이나 확장자가 아니라 파일 안에 뭐가 들어있는지로 찾는다는 게 핵심입니다. macOS Spotlight나 Windows 검색이 메타데이터와 텍스트 인덱싱에 머무르는 것과 결이 다릅니다.

Swift로 작성됐고, 공개 14일 안에 4261개의 스타를 받았습니다(저장소 통계 기준). 짧은 기간에 이 정도 반응이면 수요가 실제로 있다는 신호로 봐도 됩니다.

## 온디바이스 검색이 왜 지금 다시 이슈인가

콘텐츠 기반 검색을 하려면 보통 파일을 임베딩으로 변환해서 벡터 DB에 넣고 유사도 검색을 해야 합니다. 이걸 클라우드에서 하면 개인 파일을 외부 서버로 올려야 한다는 문제가 생깁니다.

DigUp은 이 과정을 전부 로컬에서 처리합니다. 설명에 "On-device on Mac, Windows and Linux"라고 명시되어 있으니, 세 플랫폼 모두에서 네트워크 전송 없이 동작한다는 뜻으로 읽힙니다.

개인 사진, 녹음 파일, 미공개 코드처럼 외부로 보내기 꺼려지는 데이터를 다루는 사람에게는 이 지점이 선택 기준 자체가 됩니다. 클라우드 임베딩 API를 쓸지 말지 고민할 필요가 없어집니다.

## EmbeddingGemma 2 기반이라는 것의 의미

DigUp은 Google DeepMind의 EmbeddingGemma 2를 임베딩 모델로 씁니다. 임베딩 모델의 성능이 검색 품질을 거의 전부 결정하는 구조라, 어떤 모델을 쓰는지가 도구의 실질적인 정체성입니다.

다만 EmbeddingGemma 2의 구체적인 파라미터 수, 지원 언어 범위, 벤치마크 수치는 이 저장소 설명만으로는 확인되지 않습니다. 모델 자체를 평가하려면 별도로 찾아봐야 합니다.

로컬에서 임베딩 모델을 돌린다는 건 디바이스 자원을 소비한다는 의미이기도 합니다. 대용량 영상이나 수만 개 파일을 인덱싱할 때 속도와 메모리가 어떻게 되는지는 설명에 나와 있지 않아, 여기까지는 확인되지 않습니다.

## Swift로 만든 크로스플랫폼, 실무에 어떤 변수가 있나

Swift는 애플 생태계에 최적화된 언어입니다. 그런데 설명에는 Mac뿐 아니라 Windows와 Linux 지원도 명시돼 있어, 크로스플랫폼 빌드 체계를 따로 갖췄을 가능성이 높습니다.

실무에서 도입을 고려한다면 다음을 확인해볼 만합니다.

- 각 OS별 바이너리 크기와 설치 방식이 동일한 수준인지
- Linux에서 Swift 런타임 의존성이 배포에 부담을 주는지
- 파일 변경 감지(인덱스 갱신) 방식이 실시간인지 수동 재스캔인지

이 세 가지는 설명만으로는 알 수 없는 부분이라, 실제로 설치해보기 전까지는 판단을 유보하는 게 맞습니다.

## 내 워크플로에 넣는다면 무엇을 걸림돌로 봐야 하나

개발자 입장에서 가장 먼저 걸리는 건 코드 검색 기능입니다. 설명에 "code"가 검색 대상으로 명시돼 있는데, 이게 단순 텍스트 매칭인지 코드 구조를 이해한 의미 검색인지는 나와 있지 않습니다.

두 번째는 초기 인덱싱 비용입니다. 영상과 녹음 파일까지 임베딩한다면 대용량 미디어가 많은 사용자는 초기 스캔 시간이 상당할 수 있는데, 이에 대한 수치는 저장소 설명에 없습니다.
